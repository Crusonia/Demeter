## Context and constraints

Problem, phase boundary, affected users/modules, invariants, units/time semantics,
evidence assumptions and compatibility requirements.

## Alternatives and decision

Options considered, including keeping the current design. Selection rationale,
tradeoffs and unresolved objections. Separate proposed behavior from what exists.

## Consequences and verification

Migration/rollback, version implications, data/provenance effects, tests performed
and results, tests still needed, and conditions that would trigger reconsideration.
Link the scientific RFC when model meaning changes; CI is not scientific acceptance.

## Review and interests

Actual reviewer roles, scope, relevant conflicts or none known, minority views and
maintainer rationale. An invitation to review is not an approval.
