# Public acute food-response data: source and intake design

The public [Hutelin et al. dataset](https://doi.org/10.7294/32077803.v2)
provides a new route toward a reproducible acute food-response analysis for
[#58](https://github.com/Crusonia/Demeter/issues/58) and
[#117](https://github.com/Crusonia/Demeter/issues/117).
This stage verifies source identities and two CSV headers. It implements no
participant analysis, effect estimate or clinical parameter.

The [2026 publication](https://doi.org/10.1038/s42255-026-01619-4)
compares matched whole meals in a randomized crossover study of selected
healthy-weight adults. Acute glucose and insulin measurements are relevant to
the food-to-metabolism question. They do not identify annual diabetes
progression, reversal, mortality or a continuous UPF-dose coefficient. An acute
insulin difference alone cannot establish insulin resistance.

This design feeds I-07/I-11 and F-08/T-08 in the
[input](design/04_MODEL_INPUTS.md) and
[formulation](design/05_FORMULATION_AND_TESTS.md) registers. It preserves the
[RFC-58 disease-bridge requirement](rfcs/RFC-58-food-pathway-identification.md).
Publication results were already known; this is used-source development, not
preregistration or an untouched holdout. The original goal remains incomplete.

## Source selection and rights

The publisher links to the Virginia Tech Data Repository. Its public producer
[API record](https://api.figshare.com/v2/articles/32077803), retrieved October 11,
2026, identifies version 2, published October 5, and CC0 1.0. The
[contract](validation/hutelin2026-preflight-contract-v1.json) pins the actual
metadata, README, protocol, two R-code archives and data ZIP by exact bytes,
download URL, file ID and SHA-256. Producer MD5s were also checked at acquisition.
The metadata file is a retrieval snapshot; a newly fetched API response may
differ even when the data files have not changed.

All original files remain immutable in ignored local storage. CC0 permits reuse;
the project keeps participant health records and linkable identifiers out of
GitHub. Only documentary metadata, headers, software and aggregate source-check
receipts travel here. The experimental-code archive, imaging data and unrelated
participant fields are outside this intake.

The protocol filename says May 27, 2025, while its visible page footer records
approval from March 14, 2026 to March 13, 2027. Neither date is silently treated
as the original collection period. Protocol pages 11, 12 and 19 describe optional
metabolic sessions, fasting, blood draws and exclusions, including prior
prediabetes/diabetes. Page 12 was checked visually as well as by text extraction.

## Observations the next analysis must resolve

| Source locator | Verified documentary finding | Consequence for design |
| --- | --- | --- |
| Protocol, p. 12 | Eight planned draws, a pre-meal baseline, approximately half-hour spacing thereafter and roughly three hours post-meal | Do not reconstruct actual collection times from this schedule alone. |
| Published methods, metabolic session | Baseline is 60 minutes before the meal; post-meal labels are 5, 20, 40, 60, 90, 120, 180 | The code's baseline 0 and display -20 are different conventions. The additional code label 10 needs reconciliation. |
| `3_imputation.R`, long-format time suffixes | Nine labels: 0, 5, 10, 20, 40, 60, 90, 120, 180 | These are code-selected labels; actual row coverage is uninspected. Preserve the disagreement with the protocol. |
| `1_figure_1.R`, baseline reassignment | Source time 0 is changed to -20 for plotting after AUC generation | Keep raw time, actual collection clock and display time distinct. Never integrate over the plotting shift. |
| `blood.csv` header | `insulin`, `insulin_w0`, `insulin_impute`; replicate glucose fields, `gluc_ave`, `glucose`, `a1c` | A field called raw or impute does not establish how its values were obtained. Resolve assay cleaning, replacements and derivations before choosing the endpoint. |
| `1_clean_blood_data.R` | Baseline-subtracted AUC uses `glucose` and `insulin_impute`; fasting data are merged by person and condition | Check join coverage, uniqueness, missing baselines and actual time ordering before reproducing AUC. |
| `3_imputation.R` | FAMD imputation uses other covariates; low-observation handling is explicit | Preserve observation versus imputation status; participant analysis is not admitted by reading the code. |
| Same script, final `select` before `write.csv` | Temporary `_not_imputed`, `n_gluc` and `n_ins` fields are dropped from the final output | The final derived file does not preserve these provenance fields. A replay must retain its own missingness ledger. |
| README, data-folder description; actual ZIP directory | Derived folder is empty; `data/derived/imputed_data.csv` is absent | Figure 1 consumes a file generated by upstream code. Header verification cannot reproduce its published analysis. |
| README, chamber date description | Session dates are shifted to a common origin while preserving intervals | These are not original calendar dates. Any period/sequence analysis requires separately checked linkage and interval semantics. |
| README versus code archive | README names `2_imputation.R`; delivered member is `3_imputation.R` | Use the actual member identity and record the naming discrepancy. |
| README versus indexed article methods | R 4.5.2 versus R 4.4.1 | Freeze an explicit replay environment; no R code has been executed here. |

The inspected source code preserves concentration and AUC roles separately.
An AUC is concentration multiplied by elapsed time, rather than a clinical
hazard. Selection into optional metabolic sessions is distinct from the entire
study population. A participant with two meals can also have multiple blood
draws; these are repeated observations, not independent people.

The [published methods](https://www.nature.com/articles/s42255-026-01619-4)
also describe failed draws, an early-terminated session and variable spacing
between meal sessions. Do not infer complete assays from completion of both
meal visits. Its Crossmark record was marked
[current on October 11](https://crossmark.crossref.org/dialog/?doi=10.1038%2Fs42255-026-01619-4);
that does not reconcile the documentary discrepancies or guarantee no later update.

## Reproduce the completed stage

Follow the normal [cross-platform installation](GETTING_STARTED.md). Obtain the
six exact originals using the producer URLs in the contract and save them under
its `local_filename` values in a private ignored folder. Do not overwrite a
different existing file or edit hashes to make a changed source pass.

The following command works in Windows PowerShell, macOS and Linux after those
files have been obtained:

```text
uv run python scripts/verify_hutelin_preflight.py --raw-dir data/raw/clinical/hutelin2026-documentation-20261011 --output outputs/hutelin-preflight.json
```

The output path must be new. The command is offline and rejects changed contract,
source or header bytes. It validates bounded unique unencrypted ZIP directories,
reads only the two selected CSV header lines, and hashes four selected R-code
members without executing them. ZIP decompression may buffer beyond a header;
no participant row is passed to a decoder or exported. Complete compressed ZIP
bytes are checksum-verified; the data members' full decompression/CRC is **not**
verified. There is no extraction, author-code execution, record linkage,
imputation or model fitting.

The [saved original-source receipt](validation/hutelin2026-preflight-result-v1.json)
records the actual successful local invocation. Ordinary tests use synthetic
byte streams and reconcile that receipt; CI does not acquire or open the excluded
data ZIP. A source/header match proves a reproducible selection, not scientific
validation. Technical size bounds and checksums are not model parameters.

## Next empirical stage

Before decoding records, freeze a finite selected-field coverage plan: private
person/condition/time keys; glucose/insulin provenance and missingness; actual
time support; complete and incomplete pairs; session ordering and transformed
date intervals. Retain unknowns and unmatched records, and define aggregate-only
disclosure. Resolve source transformations from methods/code before classifying
a value as observed. Avoid demographic and imaging intake unless necessary for
a specifically justified analysis.

Then specify an acute whole-meal response estimand with paired uncertainty,
baseline handling, period/sequence and missing-data sensitivity. Keep raw and
imputed analyses distinct. A numerical reproduction would still use previously
inspected source results. A clinical-state bridge, observation model, exposure
applicability and independent evaluation remain separate required work for #58.
No active evidence parameter, scenario equation or scientific-release gate changes
in this stage; current model outputs remain validation-only.
