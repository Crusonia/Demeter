# Community code of conduct

Demeter welcomes people who support, question, or reject the Food is Health
thesis. Participation does not require a particular profession, institution,
diet, commercial interest, or prior agreement with the maintainers. This code
applies in repository issues, PRs, discussions, and other project-hosted spaces,
and when someone explicitly represents Demeter.

## Working together

- Critique evidence, assumptions, methods and code. Explain the problem and what
  would test it; do not attack a person's identity or worth.
- Make room for different expertise and experience. Ask for definitions, explain
  technical terms, and correct mistakes without humiliation.
- Credit contributions, disclose material conflicts under the
  [scientific review rules](docs/SCIENTIFIC_REVIEW.md), and correct misleading
  claims when evidence changes.
- Respect boundaries and requests to stop contact. Do not retaliate against
  someone for raising a concern, disagreeing, or reporting misconduct.

Harassment, threats, discriminatory abuse, sexual harassment, doxxing, unwanted
contact, impersonation, and targeted disruption are unacceptable. This includes
abuse based on race, ethnicity, nationality, religion, age, disability, sex,
gender identity or expression, sexual orientation, or body size. Do not post
private information without permission. Never add identifiable personal health
data to the repository or public project spaces.

Good-faith scientific disagreement, negative results, correction of a maintainer,
and a supported challenge to a commercial claim are not conduct violations.
Conduct moderation must not be used to remove an inconvenient hypothesis.
Fabricated evidence or concealed conflicts are also handled through the
scientific review process; a mistaken analysis alone is not misconduct.

## Report a concern

Use [GitHub's reporting instructions](https://docs.github.com/en/communities/maintaining-your-safety-on-github/reporting-abuse-or-spam)
for content, account or repository reports. If **Report to repository admins**
is offered, that is a project-admin route. **Report abuse to GitHub Support**
and the linked GitHub contact form go to GitHub, not to a Demeter mailbox.
Available in-product options depend on permissions and repository settings;
use the contact form if an in-product option is unavailable.

This project does not currently publish a separate confidential reporting
mailbox or independent conduct committee. For sensitive reports, or concerns
about the maintainer, use the GitHub Support route without posting private
details in a public issue. GitHub applies its own platform rules; Demeter cannot
promise a response time, a particular platform action, or access to that report.

For a nonsensitive project moderation request, an issue may link the public
content and request review by [Carter Williams](https://github.com/jcarterwil).
Public issues are **not confidential**. Share only the minimum information needed;
do not repeat private or abusive material merely to create a public record.

## Moderation and reconsideration

Carter Williams is responsible for project moderation. Depending on severity,
the response may be a request to change behavior, an edit/removal of content,
a warning, a temporary interaction restriction, or removal from project spaces.
Serious threats or exposure of private information can require immediate action
without a warning. Preserve relevant evidence privately when available, minimize
redistribution of harmful content, and explain the rule and scope of the action
to affected people when doing so is safe and permitted.

A person may request reconsideration with new evidence through the same available
route. Separate the conduct decision from the scientific merits of a contribution.
If the maintainer is personally involved, seek an uninvolved reviewer where
available and disclose any independence limitation; do not claim an independent
appeal occurred when there was none. Platform abuse may be reported directly to
GitHub, including concerns about a project moderator.

Project policy changes go through PRs. This is a project-specific code; it does
not change GitHub's terms or promise authority over off-platform conduct.
